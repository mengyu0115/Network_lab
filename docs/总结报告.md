# 项目阶段总结报告

## 1. 项目定位

本项目当前定位为：

```text
面向 Qwen-VL 的图像对抗样本黑盒鲁棒性评估平台
```

项目选择图片模态作为核心研究对象。系统先使用本地 surrogate 视觉模型生成对抗图片，再调用阿里云百炼 Qwen-VL 对原图和对抗图执行同一 OCR/结构化理解任务，通过字段准确率下降判断扰动是否对主流多模态大模型产生黑盒迁移影响。

项目不做隐藏载荷投递、真实平台绕过或越权测试，只用于课程报告和授权 API 下的模型鲁棒性评估。

## 2. 当前主线流程

```text
图片样本
-> 本地 surrogate 生成对抗样本
-> 原图 / 对抗图 / 扰动图展示
-> Qwen-VL 黑盒字段抽取
-> 真实答案字段对比
-> 实验记录与报告素材保存
```

Web 页面主线顺序为：

1. 对抗样本生成
2. Qwen-VL 黑盒评估
3. 实验结果分析
4. 样本管理
5. 历史记录

`附加实验` 页保留 CLIP/BLIP 本地攻击，用于 baseline 和拓展说明，不作为答辩主结论。

## 3. 指导书要求对应

| 指导书要求 | 当前实现 | 证据文件 |
| --- | --- | --- |
| 数据样本管理 | 支持图片上传、标注、分组、版本快照和导出 | `src/data_manager/dataset_manager.py`，Web `样本管理` 页 |
| 图像对抗样本生成 | 支持 FGSM、PGD、C&W，生成原图/对抗图/扰动图 | `src/attacks/fgsm.py`、`pgd.py`、`cw.py` |
| 攻击效果评估 | 输出 L2、Linf、SSIM、预测翻转、本地指标 | `src/evaluation/metrics.py` |
| 鲁棒性分析 | 对 Qwen-VL 原图/对抗图字段准确率做对比 | `src/evaluation/blackbox_metrics.py` |
| 结果可视化与记录 | Streamlit 展示图片、指标、回答对比、历史记录 | `web/app.py`，`data/adversarial/` |
| 主流大模型评估 | 接入阿里云百炼 Qwen-VL 授权 API | `src/external_models/vision_clients.py` |

## 4. 已完成的关键改进

### 4.1 前端主线重构

前端标题改为 `Qwen-VL 图像对抗鲁棒性评估平台`，页面顺序从旧的分类/CLIP 演示调整为 Qwen-VL 黑盒评估主线。

侧边栏只保留主线生成对抗样本所需参数；CLIP/BLIP 被放入折叠区和 `附加实验` 页，避免队友误以为它们是课程主线。

### 4.2 Qwen-VL 黑盒评估

新增阿里云百炼 DashScope OpenAI-compatible API 调用能力：

```text
DASHSCOPE_API_KEY
DASHSCOPE_BASE_URL
```

支持模型：

```text
qwen-vl-plus-latest
qwen-vl-max-latest
qwen-vl-ocr
```

默认启用 `data/blackbox_cache/` 缓存，同一图片、同一模型、同一提示词不会重复请求 API，可降低费用和输出波动。

### 4.3 真实答案字段评估

为了避免把“原图本来识别错”误判为攻击成功，系统新增真实答案字段：

```text
key=value
```

只有同时满足以下条件时，才判定为严格成功：

```text
原图字段准确率 >= 80%
对抗图字段准确率下降
原本正确的字段在对抗图中变错
L2/Linf > 0
```

如果原图字段准确率低于 80%，系统会提示该样本只能作为“原图识别困难样本”，不计入严格攻击成功。

## 5. 推荐实验素材

示例图片已放入：

```text
docs/sample_images/
```

推荐用途：

| 文件 | 用途 | 报告定位 |
| --- | --- | --- |
| `课程通知截图.png` | 字段较多、适合 OCR 字段抽取 | 主成功样本优先 |
| `生成菜单截图.png` | 数字价格较多 | 成功或部分成功样本 |
| `北京天气截图.png` | 字段较少、结构清楚 | 对照或补充样本 |
| `生成成绩表截图.png` | 简单表格、原图易识别 | 鲁棒失败样本 |

每张图建议至少跑三组：

```text
epsilon=0
epsilon=0.03, alpha=0.01, iter=20
epsilon=0.05, alpha=0.01, iter=30
```

## 6. 当前完成度

功能层面已经满足指导书核心要求：样本管理、对抗样本生成、效果评估、鲁棒性分析、可视化与历史记录均已实现。

报告层面还需要队友补充最终实验结果表、页面截图和小组信息。最终结论不能只看本地 ResNet 分类准确率，应以 Qwen-VL 字段准确率下降和真实答案攻击成功为主。

## 7. 已知限制

- 商业模型只能黑盒调用，无法获取梯度，因此项目采用 surrogate-based 黑盒迁移评估。
- Qwen-VL 输出存在随机性，缓存可以降低重复实验成本，但最终报告仍建议固定模型、提示词和样本。
- 测试图选择会明显影响结果：过简单图像容易鲁棒失败，过复杂截图可能原图就识别错误。
- API Key 不能写入代码、文档或截图；如已经暴露，应重新生成 Key。

## 8. 结论

当前项目已经从旧的本地分类/CLIP/BLIP 演示，改进为围绕 Qwen-VL 的图片模态黑盒鲁棒性评估平台。项目具备可运行平台、真实商业多模态模型评估、严格成功判定、实验记录和报告/PPT 支撑材料，适合作为课程项目继续补充实验数据并完成最终汇报。
